# 設計: 家族共有とクラウド保存（バックアップ・機種変更）

2026-11-03 作成（設計: Opus / 実装: Sonnet / レビュー: Opus）。決定事項はユーザー確認済み:
Firebase（無料の Spark プラン、プロジェクトはユーザーが作る）／アカウント登録なしの「家族コード」方式／写真は小さくして共有。

## 考え方

- 共有とバックアップは同じ仕組みにする。「家族グループ」に入っていれば、データはクラウドにもある。
  1人でもグループを作れば、それがバックアップになる。機種変更は新しい端末で同じコードを入れるだけ。
- 画面の表示は今までどおり手元の `State`（AsyncStorage）から出す。クラウドとは「手元の変更を送る」「クラウドの変更を取り込む」だけをする。
  グループに入っていなければ、今までとまったく同じに動く（Firebase に一切つながない）。
- Firebase JS SDK（`firebase`）を使う。`@react-native-firebase` は使わない（AGENTS.md の方針）。Expo Go でも動く。
- 追加する依存: `firebase`、`expo-image-manipulator`（写真の縮小）。メインが入れる。

## 設定値

- `EXPO_PUBLIC_FIREBASE_API_KEY` / `..._AUTH_DOMAIN` / `..._PROJECT_ID` / `..._APP_ID` を環境変数で渡す。
  手元は `.env.local`（`.gitignore` 済み）、CI は GitHub の Secrets → ワークフローの Build の `env`。リポジトリに値を書かない。
- 値が無いとき（未設定のビルド）は共有の画面に「この版では使えません」と出して、ほかは普通に動く。

## 本人確認

- Firebase Authentication の匿名ログイン（`signInAnonymously`）。ログイン状態は `initializeAuth(app, { persistence: getReactNativePersistence(AsyncStorage) })` で保持。
- 端末が変わると uid は変わる。グループへの出入りは「家族コード」を知っているかで決める。

## データの形（Firestore）

```
households/{hid}            { code: string, members: string[] /* uid */, createdAt }
households/{hid}/members/{uid}   { name: string, joinedAt }
households/{hid}/items/{id}      Item から photo/photoOrig のファイル名を含めたもの（private の品は送らない）
households/{hid}/list/{id}       ListEntry（private の品に紐づく行は送らない）
households/{hid}/purchases/{id}  Purchase ＋ by: 名前（誰が買ったか）
households/{hid}/tags/{id}       Tag
households/{hid}/photos/{name}   { data: base64 }  // 長辺 256px に縮小。PNG は透過のまま、JPEG は品質 0.7。photo と photoOrig の両方を送る
codes/{code}                     { hid }           // 家族コード → グループ。get だけ許可、list は禁止
```

- 家族コード: 紛らわしい文字（0/O/1/I/L）を除いた英数字 8 文字。`XXXX-XXXX` で表示。
- `settings`（通知・表示・AI・外したアイコン）は端末ごと。共有しない。`householdId` は既存の `State.householdId` を使う
  （今は乱数が入っているので、新たに `State.cloud?: { hid: string; name: string }` を足し、グループ参加中だけ値を持つ）。
- 品ごとの共有: `Item.private?: boolean`（既定は共有）。品の編集画面に「家族と共有する」スイッチ（グループ参加中だけ表示）。
  private の品とその購入記録・リスト行は手元だけ。

## 同期のしかた（`src/cloud.ts` に閉じ込める）

- 送る: `update()` で state が変わったら、前の state と比べて items / list / purchases / tags の
  追加・変更・削除を見つけ、`setDoc` / `deleteDoc` を `writeBatch` でまとめて送る（500 件ごと）。比べ方は id ごとの JSON 比較。
  写真ファイル名が新しく現れたら、縮小して `photos/{name}` に送る。
- 取り込む: 4 つのコレクションを `onSnapshot`。届いたものは手元の該当コレクションを「クラウドの共有分 ＋ 手元の private 分」で置き換える。
  取り込みで変わった state は「送る」の比較元にもするので、こだまのように送り返さない。
  知らない写真ファイル名があれば `photos/{name}` を読んで `Paths.document` に書く。
- ぶつかったとき: 文書ごとに後から書いた方が勝つ（ponytail: 項目ごとのマージはしない。困ったら更新時刻つきマージにする）。
- 前回クラウドと一致していた文書（キーと JSON）を端末ごとに `AsyncStorage` の `synced:{hid}` に覚え、
  起動時（最初のサーバー回答時）に「前回・手元・クラウド」の 3 者で比べる: 手元だけ変わっていれば手元を送る／
  手元で消えていてクラウドが前回のままなら削除を送る／クラウドで消えていて手元が前回のままなら手元から消す／それ以外はクラウドが勝つ。
  これでオフライン中の変更・削除も、次につながったときに届く。取り込み後に `refresh` をやり直す。最初の取り込みは 4 コレクションともサーバーの
  回答を待つ（オフラインの空キャッシュを「クラウドは空」と取り違えない）。
- お店の並び順は文書の `o` に持つ。参加時、同じ名前のお店はクラウド側の id に寄せる（初期 4 店の二重化を防ぐ）。
- private の品を消したときに購入が共有へ漏れないよう、購入にも `private` を持つ。
- オフライン: Firestore JS SDK の既定（メモリ内の待ち行列）。アプリを閉じると未送信分は消えるが、次に開いたとき
  手元とクラウドの差を「送る」で埋める（起動時の最初のスナップショット後に、手元にしかない共有分を送る）。
- 通知の予約は各端末が自分の state から行う（今のまま）。

- クラウドから来た写真ファイル名は `^[0-9A-Za-z-]+\.(jpg|png)$` に合うものだけ使う（パスの書き換えを防ぐ）。
- 写真の送信は文書の書き込みの後に行い、失敗した名前は次の送信で送り直す。
- 参加中にバックアップを読み込むと家族のクラウドも置き換わるので、確認を出す。
- 家族コードの乱数は `expo-crypto` の `getRandomValues`。

## 画面

「わたし」タブの先頭付近に「家族と共有・バックアップ」行 → `src/app/share.tsx`:

- 未参加:
  - 説明（1人でも作ればバックアップになる・機種変更は同じコードを入れる・コードを知っている人は誰でも入れる）。
  - ［家族グループを作る］→ 自分の呼び名を聞く → 手元のデータをクラウドへ送る → コードを表示。
  - ［コードで参加する］→ コードと呼び名を入れる → 手元に品があれば「手元のデータを合わせる／クラウドのデータで置き換える」を選ぶ → 参加。
- 参加中:
  - 家族コード（大きく表示、［コピー］［共有］）。
  - メンバー一覧（呼び名）。自分以外を［外す］（古い端末の整理にも使う）。外された人は今のコードを知っているので、
    外したあと続けて「コードも作り直しますか？」と聞く（作り直さないと同じコードで入り直せる）。
  - ［コードを作り直す］（古いコードでは入れなくなる。メンバーはそのまま）。
  - ［グループから抜ける］（手元のデータは残る。以後はクラウドに送らない）。
- 購入履歴（品の詳細・すべての履歴）に、参加中は「誰が」（`by`）を小さく出す。

## セキュリティルール（`firestore.rules` をリポジトリに置き、ユーザーがコンソールに貼る）

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    function signedIn() { return request.auth != null; }
    function hh(hid) { return get(/databases/$(db)/documents/households/$(hid)).data; }
    function member(hid) { return signedIn() && request.auth.uid in hh(hid).members; }

    match /codes/{code} {
      allow get: if signedIn();
      // そのグループの今のコードと同じ名前でしか作れない（先に households の code を書き換えてから作る）
      allow create: if signedIn() && member(request.resource.data.hid) && hh(request.resource.data.hid).code == code;
      allow delete: if signedIn() && member(resource.data.hid);
    }
    match /households/{hid} {
      allow create: if signedIn() && request.resource.data.members == [request.auth.uid];
      allow read: if signedIn() && request.auth.uid in resource.data.members;
      // メンバーは何でも更新できる / 非メンバーは「joins.{自分の uid} に今のコードを書いて自分を足す」だけ。
      // 添え書きを uid ごとにするのは、他人の残した値に便乗させないため。
      // hid を知っていても今のコードを知らなければ入れない（外した端末はコードを作り直せば戻れない）
      allow update: if member(hid)
        || (signedIn()
            && request.resource.data.members == resource.data.members.concat([request.auth.uid])
            && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['members', 'joins'])
            && request.resource.data.joins.diff(resource.data.get('joins', {})).affectedKeys().hasOnly([request.auth.uid])
            && request.resource.data.joins[request.auth.uid] == resource.data.code);
      match /{col}/{id} {
        allow read, write: if member(hid);
      }
    }
  }
}
```

- 非メンバーは households を読めないので、参加は「`codes/{code}` を get → hid を知る → members に自分を足し `joins.{自分の uid}` に
  コードを添えて update」の順。ルールは `joins[自分の uid] == 今の code` を確かめる（uid ごとなので他人の値に便乗できない）ので、hid を知っている外された端末でも、
  コードを作り直したあとは戻れない。
- コードの作り直しは「households の code を書き換え → `codes/{新}` を作る → `codes/{旧}` を消す」の順（ルールが今の code と同名しか作らせない）。
- `codes` は list 禁止なので総当たりで探すしかない（紛らわしい文字を除いた 31 文字の 8 桁 = 31^8 通り）。
- 最後のメンバーが抜けても household のデータは残る（ponytail: 掃除は手作業。必要になったら Cloud Functions 等で）。

## 検証項目

1. 未参加・設定値なしで、今までどおり動く（Firebase に通信しない）。
2. 端末 A でグループを作る → 端末 B でコード参加 → 品・リスト・購入・お店・写真が両方に出る。チェックがもう一方に数秒で届く。
3. private の品は相手に出ない。
4. B で古い端末（A）を外すと、A はクラウドを読めなくなる（A の手元のデータは残る）。
5. コードを作り直すと、古いコードでは参加できない。
6. 機種変更: 新しい端末で同じコードを入れると全部戻る（写真は縮小版）。
